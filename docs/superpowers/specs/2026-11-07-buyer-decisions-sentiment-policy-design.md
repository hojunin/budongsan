# 제품 가치 확장 — 지금 사도 되는가, 전망·심리·정책

2026-11-07 · 사용자 추가 요구 반영. [기존 제품 설계](2026-11-07-real-estate-content-platform-design.md), [데이터 계약](../../data/2026-11-07-interface-contract.md), [인사이트20개](../../insights/2026-11-07-composite-insights.md)를 확장한다. 아래는 실제 시장 판단·가격 예측·정책 효과 검증 결과가 아니라 구현할 기능의 설계다.

## 1. 제품의 중심 질문 변경

사용자가 독자에게 주려는 가치: **지금 집을 사도 되는지, 가격이 더 오를지, 시장참여자의 심리는 어떤지, 특정 정책에 대해 어떻게 생각하는지**를 이해하도록 돕는다. 기존 ‘예쁜 분석과 콘텐츠’는 이 질문에 답하는 수단이다.

첫 화면의 주 진입을 네 질문으로 제안한다. 예산·가격분포·심리·정책을 모두 동등한 카드20개로 펼치지 않는다.

| 주 진입 | 독자가 받는 결과 | 기존/추가 근거 |
|---|---|---|
| 지금 사도 될까? | 내 가정에서 감당 가능한 부분·부족한 부분·추가 확인할 항목 | I05/I08/I09/I15 + I21/I22 |
| 가격은 더 오를까? | 상승 쪽/하락 쪽 관측 근거, 반대 근거, 전망을 바꿀 조건 | I01/I02/I04/I16/I17 + I23/I24 |
| 사람들은 어떻게 느낄까? | 누가 무엇에 응답했는지와 실제 거래의 일치/엇갈림 | I10/I11/I12 + I25/I26 |
| 이 정책은 어떻게 받아들일까? | 정책 내용·시행 상태·집단별 의견·관측 변화·내 확인사항 | I27/I28 + 공식 원문 |

공개 기본 화면은 지역·매매/전세/월세에 맞는 시장 맥락을 먼저 제공하고, 개인 입력은 ‘내 조건으로 보기’에서 선택한다. 첫 버전의 현금·소득·부채·지출 입력은 브라우저 메모리의 임시 계산에만 사용하고 서버/URL/로그/분석이벤트/초안 자동저장으로 보내지 않는다. 새로고침하면 초기화하며 계정 동기화·자동 재방문 복원은 제공하지 않는다. 사용자가 결과를 내보낼 때만 포함 항목을 미리 보여 주고 명시적으로 선택하게 한다. 개인 자금 입력과 정책 설문 동의는 분리한다. 향후 영구저장을 추가하면 저장위치·보관기간·삭제경로를 새 계약으로 먼저 확정한다. 금액·소득·부채는 개인 가정임을 표시하며 공유 URL/출력물에 기본 포함하지 않는다. 일반 독자는 개인 입력 없이 읽을 수 있다.

답은 각 화면의 첫 줄에 짧게 제시한다. ‘내 조건’은 기준 충족/부족 금액, ‘전망’은 작성자가 검토한 조건부 판단과 반대근거, ‘심리’는 출처별 확인된 변화, ‘정책’은 확인된 의견 차이와 개인에게 확인할 항목을 먼저 보여준다. 기본 작성 틀은 **현재 요약 → 근거2개 → 반대/미확인 근거 → 판단을 바꿀 조건 → 다음 행동**이다. 이를 생략한 지표 목록만으로 답을 대신하지 않는다. 관측이 없는 경우는 부족한 자료를 밝히고 결과를 비운다.

시장 전망과 개인 감당 가능성은 별도 축이다. 시장 상승 근거가 많아도 개인 부담이 클 수 있고, 개인 자금 여력이 있어도 단기 가격은 하락할 수 있다. 두 축을 곱한 ‘매수 적기87점’이나 자동 ‘사라/팔아라’ 등급을 만들지 않는다.

## 2. 추가 인사이트8개 — I21–I28

### I21. 집값이 흔들려도 내 자금 계획을 유지할 수 있나?

- **입력/결합:** 사용자가 입력한 집값·보유 유동현금·월 세후 실수령액·매수후 생활지출·기존 부채상환·매수후 주거유지비·가정 대출원금/기간/방식·취득/거래비용·남길 현금. 생활지출은 기존/신규 대출상환·주거유지비를 제외해 중복차감하지 않는다. 보유현금에 묶인 임대보증금을 자동 포함하지 않고 반환예정액/시점을 별도로 확인한다. 잔금 전 반환이 불명확하면 그 자금은 사용가능현금에 넣지 않는다. 입력하지 않은 값을 개인의 사실처럼 채우지 않는다.
- **계산:** `거래후현금=보유현금-(집값-가정대출원금)-초기비용`, `월잔여=월세후실수령액-매수후생활지출-기존상환-신규상환-매수후주거유지비`. 사용자 선택 금리+1/+2%p·소득감소 시나리오에서 재계산. 가격하락은 담보/순자산 평가 변화로 별도 표시하며 대출 만기/매각 가정 없이 즉시 현금 손실로 합치지 않는다.
- **표현:** ‘현재 가정에서 월 잔여 {값} / 남는 현금 {값} / 금리상승 때 {값}’. 필요 현금·부족분과 사용자가 정한 여유 기준을 표시. 무입력·불완전 입력은 결과 보류. 첫 버전 소득은 월 세후 실수령액만 받는다. 세전 연소득에서 추정 공제하지 않으며 실수령액을 모르면 월잔여 결과를 비운다. 주거유지비는 사용자의 관리·유지·세금 등 월환산 가정이며 0을 자동 대입하지 않는다.
- **결과/한계:** ‘내가 정한 여유 기준 충족/부족/확인 필요’이지 승인된 대출·객관적 안전 판정이 아니다. DSR/LTV와 은행승인은 현재 정책·상품·개인 심사와 별도 검증하며 임의로 보장하지 않는다.
- **준비:** 기존 예산함수 재사용 후보 + 신규 개인 입력/검증 필요. 첫 릴리스는 명시적 가정 산술까지, 정책 적격 판정은 보류.

### I22. 지금 매수와 6·12개월 대기는 어떤 조건에서 달라지나?

- **입력/결합:** 현재 집값/현금·임대 보증금·월세·저축 가능액·가정 금리, 미래 매수가격 변화·미래 대출 조건·초기비용. 모든 미래값은 사용자 시나리오, 확률 없이 표시한다.
- **계산 범위:** 첫 버전은 **대기기간 동안의 현금·임대 지출·향후 매수시 필요현금과 상환액의 시나리오 비교**다. 각 시점의 현금 출납을 중복 없이 반영한다. 보증금은 반환 시점/가능성 가정을 별도 표시하며 소비비용으로 전액 차감하지 않는다. 저축 가능액은 현재 임대료·생활지출·기존상환을 모두 차감한 월 순저축액으로 고정하며 같은 지출을 또 차감하지 않는다. 출발 현금은 임대보증금과 분리한다. 보증금 반환은 확인한 반환시점에 한 번만 유입하고 미래 계약 보증금/구매지출도 시점별로 한 번만 반영한다. 저축 투자수익은 별도 입력이 없는 첫 버전에서0 가정임을 표시한다.
- **그래픽:** 미래 집값 변화×금리 변화의 표. 셀에는 ‘미래 매수 필요현금/월상환’을 표시하고 현재 매수 가정과 나란히 둔다. 사용자 가정가격0%를 중앙선으로 두어 모델 예측 중심값처럼 보이게 하지 않는다.
- **한계:** 매수 후 주거편익·유지/보유/매도비용·순자산·세금·투자수익의 동일기간 비교가 갖춰지기 전 ‘기다리면 이득’, 총수익·매수vs임차 손익분기점을 출력하지 않는다. 총비용/순자산 모델은 별도 후속 범위다. 기본 미래 집값 변화는 사용자가 선택하며 ‘예상 상승률’을 자동 입력하지 않는다.
- **준비:** 신규 시나리오 엔진/현금흐름 fixture 검증 뒤 가능. 기존 월상환 차트만으로 제공하지 않는다.

### I23. 가격 상승 기대와 실제 수요·거래는 같은 방향인가?

- **입력/결합:** 확보 후 KB 가격전망지수(현재 수집 안 함), KB 매수자/매도자 응답·거래활발지수, R-ONE 가격·수급, I01 실거래의 각각 관측 기간·범위. 미래전망 응답과 과거 관측값을 구분한다.
- **출력:** ‘가격 상승을 예상하는 응답은 {방향}, 매수자 많음 응답은 {비중}, 관측 거래는 {방향}’처럼 동시에 보여 준다. 전망 기간/주택유형/응답자/지역이 다르면 동일 모집단 비교를 보류하거나 전국 배경 패널로 분리한다.
- **그래픽:** 기대/수급/거래의 독립 행과 근거문장. 상승·하락 근거의 개수를 세어 확률이나 합성점수로 바꾸지 않는다. 반대 방향·중립·미수집도 같은 위계로 표시한다.
- **한계:** 기대심리가 높다는 것은 가격상승 확률/상승률이 아니다. 현재 심리지수로 6개월 뒤 집값을 확정하지 않는다. 전망 진입에는 `{지역/대상, 전망기간, 현재 견해, 가장 강한 근거, 반대근거, 견해를 바꿀 관측 조건, 작성자/작성시점}`의 짧은 편집 블록을 필수 출력으로 둔다. 증거가 부족하면 ‘판단 유보’와 결정적으로 부족한 근거를 구체적으로 표시한다. 편집 견해는 원 관측값과 다른 시각 블록으로 두고 작성자가 검토한 버전만 발행한다.
- **준비:** 기존 KB/R-ONE 경로는 원값/기간 검증 필요, KB 전망의 명세·사용권·실응답 확인 전 해당 행 보류.

### I24. 상승·하락 전망을 다시 점검할 조건은 무엇인가?

- **입력/결합:** 사용자가 저장한 지역의 가격/거래/임대·심리·공급 관측, 기준 release, 사용자가 선택한 비교기간/변화 조건. 새 배치 전후 같은 정의의 관측을 대조한다.
- **출력:** ‘지난 리포트 뒤 거래는 {변화}, 심리는 {변화}, 자료 {누락}. 이 변화로 기존 견해를 재검토할 수 있습니다.’ 변화가 없어도 그 사실을 표시한다. 정정으로 바뀐 값은 새 시장변화와 구분한다.
- **조건:** ‘가격이 향후 오를 조건’이라는 인과 규칙 대신 ‘확인할 관측 조건’이다. 임계값·기준기간은 명시하고 데이터주도 최적화로 과거 수익을 높인 기준을 검증 없이 적용하지 않는다. 미래성과를 약속하지 않는다.
- **그래픽/행동:** 전망 노트 옆 ‘유지되는 근거/달라진 근거/미확인’ 비교. 알림은 선택사항이고 이번에 스케줄·알림을 등록하지 않는다.
- **준비:** 기존 관측 일부로 시작 가능하나 릴리스 이력/정정 식별과 필수 입력 완결이 선행. 전 데이터가 없으면 종합 상태를 내리지 않는다.

### I25. 출처·질문·응답대상이 다른 시장 인식은 어떻게 나타나는가?

- **입력/결합:** KB 공인중개업소 응답비중/지수, 추가 국토연구원 매매·전세 소비심리, 한국은행 주택가격전망CSI. 각 조사 대상·문항·지역·기준기간·응답 전망기간·산식을 개별 메타데이터로 가진다.
- **출력:** 같은 패널3개를 서로 다른 출처/모집단 제목 아래 둔다. 국토연구원 매매/전세 지수는 시장부문이지 응답자를 매수자/임차인으로 분리했다는 뜻이 아니다. 확인된 응답집단 외 집단별 심리를 지어내지 않는다.
- **계산/한계:** 각 지수의 원수치와 자기 전기 대비 변화만 계산하고, 서로 다른 지수의 원값 차이를 ‘집단간 심리차이 X점’으로 계산하지 않는다. 기준100·구간 분류도 출처 정의가 달라 일괄적용 금지. 전국 CSI를 특정 단지 심리로 축소 표시하지 않는다.
- **준비:** KRIHS·CSI는 공식 통계 존재 확인, 구체 API/파일·표/항목코드·이용권·실응답 미확정. 기존 자료가 있는 부분만 독립 표시하고 불완전 조합을 전체 시장심리로 명명하지 않는다.

### I26. 기대가 바뀌어도 실제 거래는 따라오지 않는가?

- **입력/결합:** 같은 지역/유형에 대해 검증된 전망 조사 시계열과 계약월 실거래/I10·I11 구성. 전국 전망만 있으면 전국 범위가 완결된 거래를 확보하기 전 서울·경기 거래와 동일범위 추적 계산은 차단한다.
- **표현:** ‘{기간} 기대응답 변화 / {별도 완료기간} 관측 거래 변화’의 시차/불일치 보기. 전망 시점에 알려진 데이터 release만 저장한다. 미래 관측을 사용하는 추적은 실제 관측이 완료된 뒤 별도 ‘사후 관찰’로 표시한다.
- **한계:** 조사와 거래가 같은 사람을 추적하는 패널이 아니다. 거래가 줄었다고 ‘공포/관망’ 감정을 확정하지 않는다. 검색량·기사량은 관심의 대리지표로만 별도 표시한다. 임의 시차 상관을 가격 선행예측 모델로 승격하지 않는다.
- **준비:** 대상 지역/시간·조사범위 검증 뒤 제공, 전국 거래 미보유 시 전국 종합 추적 보류. 예측 모델과 구분.

### I27. 특정 정책에 대한 찬반·예상 영향·우려는 어떻게 다른가?

- **입력 우선순위:** ① 표본·문항·의뢰기관·조사시점·방법이 공개되고 이용권이 있는 외부 조사 ② 동의한 사이트 방문자의 자발적 응답 ③ 사용권을 확인한 기관/전문가의 공개 견해. 세 출처를 합산하지 않는다. 언론 기사 제목의 긍부정을 국민 찬반으로 바꾸지 않는다.
- **질문 분리:** ‘정책 찬성/반대/유보’, ‘집값에 미칠 예상 영향(상승/변화없음/하락/모름)’, ‘내 주거계획 영향(별도 범주)’, ‘주요 우려(복수선택)’를 별도 문항으로 둔다. 가격하락 예상=정책반대라고 분류하지 않는다.
- **집계:** 정책버전/문항버전/응답기간/자발적 역할 구분별로 단일선택은 `범주를 고른 유효응답 레코드 수/해당 문항의 유효응답 레코드 수`를 계산한다. 주요 우려 복수선택은 `해당 항목을 선택한 유효응답 레코드 수/해당 복수선택 문항 유효응답 레코드 수`로 항목마다 계산해 비율합이100%를 넘을 수 있음을 표시한다. 선택한 항목 총합을 분모로 쓰지 않는다. ‘우려 없음/모름’은 다른 항목과 동시선택할 수 없는 명시적 선택지, 무응답은 별도 제외수로 둔다. 익명 상태에서 사람의 고유성을 검증하지 못하면 응답수를 사람수로 명명하지 않는다. 무응답·모름을 별도로 보존한다. 역할은 매수검토/보유/임차/중개업 등 **복수선택 가능**이라 역할별 집단은 겹친다. 역할별 합계를 전체 고유 응답자수처럼 합산하지 않는다.
- **노출:** 자발 응답은 ‘이 사이트 응답자’로 표시, 모집단 대표성/오차범위 주장 금지. 역할 셀 n<30은 비율/자유답변을 공개하지 않는 초기 개인정보·안정성 정책으로 두며, n30도 대표성이나 재식별 방지의 보장은 아님. 희소 역할/응답 조합은 n과 관계없이 추가 집계/비공개 처리하며 원문 자유답변은 별도 검토 없이 공개하지 않는다. 로그인 없는 수집은 반복응답 방지 한계를 명시한다. 연락처·정밀주소 수집 없이 익명/가명 최소설계, 동의·보관기간·삭제 절차는 구현 전 확정한다.
- **정성 견해:** 정책효과 예상·공정성·집행가능성·우려 축으로 편집자가 근거 링크를 붙여 요약한다. 인용 권한·문맥/날짜 검토, 반대근거도 표시. 정성 자료에 인구비율을 붙이지 않는다. LLM분류는 검토 보조이며 자동 여론 판정으로 발행하지 않는다.
- **준비:** 신규 설문/조사라이선스/편집 도구가 필요. 현재 RSS 메타데이터만으로 정책 찬반을 생성하지 않는다. 이번에 응답수집을 시작하지 않는다.

### I28. 정책 발표·시행 전후에 실제 무엇이 달라졌나?

- **입력/결합:** 공식 원문의 발표일·시행일·적용대상·예외·유효버전, 성숙한 계약월 거래·가격·심리의 실제 관측기간. 기사일을 시행일로 대체하지 않는다.
- **계산:** 사전에 정한 같은 길이의 전/후 관측창과 실제 기준일을 표시. 계절성·금리·다른 정책·지역구성·신고지연을 별도 동시 변화로 기록한다. 시행 후 관측창이 덜 끝나거나 수집 미완료면 결과를 비운다. 기간/지표/창 선택을 결과를 보고 바꿨다면 탐색분석으로 명시한다.
- **그래픽:** 발표·시행 두 선의 정책 타임라인, 지표별 독립 차트와 실제 데이터 cutoff. UI 제목은 ‘발표/시행 전후 관측’이며 ‘정책효과 ±X%’가 아니다. 의견(I27)은 별도 층.
- **개인 연결:** ‘내가 확인할 적용 항목’은 공식 근거와 조건을 제시한다. 현재 규정/경과조치가 검증되지 않으면 내 적격·대출한도를 계산하지 않고 원문 확인으로 연결한다.
- **한계/준비:** 단순 전후 차이는 정책의 인과효과가 아니다. 실제 효과 추정이 필요하면 노출/대조집단·선행추세·동시충격·정책중복을 다루는 별도 연구 설계를 먼저 검토한다. 원문 사용권/정책 구조화·시점 검증 뒤 제공.

## 3. 답을 보여 주는 그래픽 문법

- **지금 사도 될까:** 현금·월잔여·충격시나리오 세 줄. ‘가능/불가’ 하나보다 부족분과 바꿔 볼 입력을 제공한다.
- **더 오를까:** 상승을 지지하는 관측/반대 관측/미확인의 근거표. 대칭 배치는 수량·증거가 동등하다는 뜻이 아니다. 각 주장에 기간·출처·방법론과 작성자 견해 여부를 붙인다.
- **참여자 심리:** 출처/응답자별 작은 차트. 기관지수·기사관심·실제거래를 같은 온도계로 합치지 않는다.
- **정책 반응:** 찬반과 가격예상영향을 별도 막대/표로 표시. 하나의 긍정/부정 색에 합치지 않는다. 표본/조사기간/출처 종류를 첫 화면에 보인다.
- 390px에서 네 질문은 한 열의 짧은 진입으로 둔다. ‘지금 매수’는 월잔여/거래후현금과 충격 결과, ‘전망’은 조건부 한 문장과 핵심/반대 근거, ‘심리’는 조사대상/기간과 한 출처의 값, ‘정책’은 버전/시행상태와 출처 종류를 먼저 보여 준다. 전망/정책에 억지로 요약 숫자 두 개를 만들지 않는다. 조사 탭을 옮겨도 출처·응답대상·문항·기간·범위는 해당 패널에 남긴다. 색은 대표색/지역색/상승하락 의미를 분리하며 ‘정책 찬성=초록, 반대=빨강’ 같은 평가색은 쓰지 않는다. 탭/키보드·대체표와 출력물의 조건 보존은 기존 계약을 따른다.

## 4. 예측을 나중에 붙일 경우의 별도 출시 조건

사용자가 원하는 ‘가격이 더 오를까’에 대해 처음에는 근거와 조건부 전망을 제공한다. 확률·예측 구간을 출력하는 기능은 별도 제품이다. 개발한다면 대상(공식 지수/거래 중간가격)·지역·3/6/12개월 중 하나의 기간을 고정하고, 해당 시점 공개자료만 쓰는 rolling-origin 검증·단순 기준선 비교·보류 기간 평가·구간포함률/오차·확률보정·개정자료 누수 점검이 필요하다. 외부 연구전망도 발표시점/전망대상/기간/이용권을 표시한다. 현재 데이터나 설계 검사만으로 예측 정확도/상승확률을 광고하지 않는다.

## 5. 추가 데이터와 명세 확인 수준

- [KB 시장심리 공식 설명](https://data.kbland.kr/kbstats/psychology-of-housing-market): 표본 공인중개업소 설문, 매수우위지수 `100+매수자많음 비중−매도자많음 비중`. 지수 이름을 매수자의 협상 우위로 곧바로 번역하지 않는다. 현재 원자료 경로와 전망 신규항목은 별도.
- [한국은행 금융·경제 스냅샷](https://snapshot.bok.or.kr/dashboard/C): 주택가격전망CSI는 현재 대비1년후 전망 설명. 현재 ECOS 전송/series 계약 미확정 상태를 그대로 유지한다.
- [국토연구원 공식 자료 안내](https://kremap.krihs.re.kr/menu6/ReportView?bID=8971&kind=54&pID=930): 월간 공표자료 및 KOSIS 제공 안내. 제공표·API 항목·최신 조사대상/임계구간·이용권을 확인하기 전 코드/임계값을 만들지 않는다. 과거 보고서의 구간을 현행 모든 심리지수에 적용하지 않는다.
- [네이버 검색어트렌드 공식 API](https://developers.naver.com/docs/serviceapi/datalab/search/search.md): 선택기간/검색어그룹의 상대 검색지표. 관심의 후보 데이터일 뿐 감정/정책 찬반 데이터 아님. 요청 조건/정규화가 다른 조회 결과를 절대 검색건수처럼 비교하지 않는다.
- 정책 원문은 [기존 공식 RSS/파일 계약](../../data/2026-11-07-interface-contract.md#3-api와-rss크롤링을-구분하는-수집-계약)을 따른다. 본문·첨부 활용권은 별도 검증한다.

## 6. 구현 순서와 검토

1. 기존 지표로 가능한 ‘내 조건+시장 맥락’의 화면부터 시안화하고 I21의 명시적 가정 산술을 검증한다.
2. 심리 출처/문항/범위 메타데이터를 확정한 행부터 I23/I25를 제공. 빠진 행은 자료 없음으로 둔다.
3. 공식 정책 타임라인 I28과 근거가 있는 외부 견해를 먼저 편집하고, 사이트 설문 I27은 동의·보관·반복응답·문항 버전이 정해진 뒤 만든다.
4. 대기 시나리오 I22, 이력 관찰 I24/I26는 시간/자료 누수 테스트 뒤. 가격 예측 모델은 별도 승인·검증 범위로 남긴다.

문서만 확장했다. 실제 개인 판단/시장 전망/정책 의견 비율을 계산하거나 응답 수집·배포·스케줄 생성은 하지 않았다.

## 7. 독립 검토 반영

[방법론 검토](../../reviews/2026-11-07-decision-sentiment-methods-review.md)와 [제품·편집 검토](../../reviews/2026-11-07-decision-sentiment-product-review.md)를 받았다. I21 세후 현금 기준/임대보증금 반환/입력 메모리 경계, I25 실제 조사대상 제목, I27 복수선택 분모·중복 역할·재식별 주의, 전망의 필수 편집 답변과 질문별 모바일 위계를 보완했다. 검사·재검토 판정은 각 보고서에 남긴다. 신규 소스·설문·예측의 운영 보류는 유지한다.
