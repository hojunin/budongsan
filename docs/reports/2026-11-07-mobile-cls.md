## 조건과 범위

- 완성된 `dist`의 독립 복사본을 `http://localhost:3001`에서 제공했다. 공유 워크스페이스의 빌드·데이터 캐시 변경 영향을 피하기 위한 고정 스냅샷이다.
- Chrome 모바일 에뮬레이션: 390×844, DPR 3, 터치 활성, CPU 4배 감속, 다운로드 9 Mbps, 업로드 1.5 Mbps, 네트워크 지연 50ms. 브라우저 HTTP 캐시 비활성. 라이트 모드, 일반 모션 설정.
- 각 페이지 3회, 총 18회 유효 측정. 새 문서의 첫 스크립트에서 Layout Instability API 관찰을 시작했다. 문서·폰트·필터·차트가 준비된 뒤 1.5초 더 기다려 초기 값을 기록했다.
- CLS는 recent-input 항목을 제외하고 1초 미만 간격·최대 5초의 세션 윈도 중 최대 점수로 계산했다. 모든 이동의 단순 합계와 구별했다. 계산 코드에는 윈도 경계·입력 제외·5초 상한 자체 검증이 있다.
- 그 후 칩 삭제(지역 비교·KB), 표 검색/초기화(지역 비교·단지), 금리 변경(예산), 차트 확대/범례(차트가 있는 5개 페이지)를 수행했다. 자동 조작은 입력 직후 500ms 제외 혜택 없이 관찰했다. 각 조작 후 1.2초를 더 관찰했다.
- 공유 개발 서버에서의 앞선 측정은 다른 프로세스의 캐시 갱신으로 중단됐다. 해당 불완전 회차와 이전 샘플 데이터 기반 수치는 위 표에 합산하지 않았다.
- 원시 측정: [2026-11-07-mobile-cls.json](./2026-11-07-mobile-cls.json). 실제 모바일 기기 및 운영 사용자 분포 측정은 아니다. 선택한 시나리오 밖의 모든 가능한 조작을 보장하지 않는다.

## 원인과 이번 수정

- Tom Select 칩을 삭제하면 후속 칩의 flex 레이아웃 위치가 바뀌었다. 칩/입력의 레이아웃 원점을 고정하고 transform으로 위치를 지정해 삭제·caret 이동을 처리했다. 일반 모션에서는 transform 전환만 사용하고, reduced-motion에서는 전환을 생략한다.
- 초기 로딩에서는 Observable의 빈 동적 영역이 실제 필터·KPI·차트로 바뀌며 뒤 콘텐츠를 밀어낸다. 대표 기록에 필터, `.kpis`, 차트 카드와 footer의 큰 수직 이동이 남는다. 이번 수정은 칩 삭제에 한정하며, 초기 로딩 공간 예약 문제는 해결되지 않았다.
- [web.dev의 CLS 기준](https://web.dev/articles/cls)에 따르면 좋은 점수는 0.1 이하이며, 이 측정의 4개 데이터 페이지는 0.25를 넘었다. 예산 계산기도 3회 중 최대 0.110이었다.
