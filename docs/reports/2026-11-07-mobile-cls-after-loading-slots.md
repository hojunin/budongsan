## 변경

- 필터의 개별 필드를 정적 HTML에 배치하고, 입력/선택·체크 옵션·범위 입력·토글 각각의 높이를 미리 확보했다. 검색 모드의 조건부 필드는 실제 모드에 맞춰 표시한다.
- KPI 4개의 정적 슬롯과 차트·표의 정적 슬롯을 추가했다. 빈 Observable 셀이 실제 컴포넌트로 교체돼도 카드와 주변 콘텐츠의 위치가 유지된다.
- 데이터 상태 배너, 단지 제목과 예산 경고도 공간을 확보했다. 실데이터에서는 예약한 배너 위치에 데이터 상태를 안내한다. 샘플 경고 문구는 유지했다.
- 한글 폰트 교체로 설명문 줄 수가 바뀌던 시장 요약은 문구 높이를 확보했다. 필터는 시스템 글꼴을 사용해 선택 옵션의 가로 재배치도 방지했다.
- 첫 측정에서 남은 토글 플레이스홀더 높이 차이도 수정했다. 빈 결과에서는 무한 로딩처럼 보이는 플레이스홀더 대신 상태 문구를 표시한다.

## 측정 조건

- Chrome 모바일 에뮬레이션, 390×844, DPR 3, CPU 4배 감속, 다운로드 9 Mbps/업로드 1.5 Mbps, 지연 50ms, 브라우저 HTTP 캐시 비활성, 라이트 모드/일반 모션.
- 이전 비교군은 `localhost:3001`, 슬롯 수정 확정 빌드의 독립 복사본은 `localhost:3004`. 두 빌드의 Parquet 첨부 파일 해시가 동일함을 확인했다. 측정 중 빌드·캐시 변경 영향을 막기 위해 각각 정적으로 고정했다.
- 새 문서가 실행되기 전 관찰을 설치하고 폰트·필터·차트가 준비된 뒤 1.5초 더 관찰했다. 이후 칩 삭제, 빈 표 검색/초기화, 금리 변경, 차트 확대/범례를 페이지별로 실행했다. 각 조작 후 1.2초를 더 관찰했다.
- 세션 윈도 CLS와 원시 이동 합계를 구분했다. 자동 조작은 클릭 직후 제외 혜택에 의존하지 않는다. 계산 코드의 1초 윈도·5초 상한·입력 제외 자체 검사도 통과했다.
- 실기기·운영 사용자 RUM 측정은 아니다. 모든 기기·네트워크·임의 조작에서 항상 0임을 보장하는 결과는 아니다.

## 검증과 재현

```sh
npm run build
CLS_BASE_URL=http://localhost:3004 node scripts/measure_cls.mjs http://127.0.0.1:53626 /tmp/cls.json 3
node scripts/check_cls_report.mjs /tmp/cls.json
CLS_BASE_URL=http://localhost:3004 node scripts/check_chips.mjs
CLS_BASE_URL=http://localhost:3005 node scripts/check_ui.mjs
```

`measure_cls.mjs`는 실행 중인 Chrome의 실제 디버깅 포트로 바꿔 실행한다. 정적 빌드 서버와 포트 역시 환경에 맞게 준비한다. 회귀 검사 예산은 전체 CLS 0.01, 조작별 원시 이동 합계 0.001이며 이번 측정값은 모두 0이었다.
