# 타이포그래피·숫자·모바일·접근성 디자인 리뷰

검토일: 2026-11-07. 대상: https://apt-insight.pages.dev 의 홈, /trades, /regions, /complexes, /budget. 기본 dark 모드에서 1440×1000, 390×844를 직접 확인했고 /regions 차트와 /budget을 320×740에서도 확인했다. 스크린샷은 /tmp/apt-type-review/ 에 있다. 로컬 src/style.css, src/components/charts.js, src/components/table.js와 trades/regions/budget 소스를 근거로 보완했다. 배포 화면과 진행 중인 로컬 수정은 같다고 가정하지 않는다.

## 판단

현재 시각적 질서는 안정적이고 숫자의 tabular-nums·우측 정렬·대체 색상·명시적인 단위는 좋은 기반이다. 그러나 카드에 남는 공간에 비해 설명과 수치 축은 작다. 모바일에서 글자를 더 줄여 정보량을 유지하는 대신, 비교 항목·축 눈금·필터의 노출량을 줄여 주요 숫자와 맥락을 함께 읽도록 해야 한다. 390 및 320의 확인한 화면에는 문서 전체 가로 넘침이 없었다.

## 우선순위별 개선

1. **P1 — 모바일 표의 숨겨진 값에 키보드로 도달할 수 있게 한다.** 단지 최근 거래 표는 390에서 날짜와 가격만 남기고 면적·층·정상 여부를 접는다. 실제 DOM의 +는 `div.tabulator-responsive-collapse-toggle`, tabindex=-1, role/aria-expanded 없음. 셀은 12.8px, 행은 실측 50px이나 토글은 CSS 외곽 24×24px이고 실측 content width는 16px이다. 숨겨진 항목을 여는 기능이 마우스 클릭에 의존한다. 토글을 이름 있는 button으로 제공하고 aria-expanded를 갱신하며 Enter/Space로 펼친다. 44px의 행 내 히트영역을 제공하되 아이콘은 작게 유지한다. 수용: Tab → ‘거래 상세 펼치기’ → Space → 면적/층/거래 상태 읽기 → 다시 닫기가 가능하고 포커스가 남는다. 근거: complexes-table-390.png, components/table.js.

2. **P1 — 차트의 비교 기능에 키보드·비시각 대체를 준다.** /regions 320에서 interactive-chart 내부 tabIndex≥0 요소는 0개였다. 범례는 1/10 페이지이며 최대 6지역×여러지표를 한 번에 그릴 수 있어 모바일에서 어떤 선을 보고 있는지 잃기 쉽다. charts.js의 role=img, aria.enabled와 시리즈 이름만으로 범례 토글·기간 확대·개별 데이터 읽기는 대체되지 않는다. 기존 필터/요약표를 키보드로 이용 가능한 대안으로 연결하고 선택한 시리즈·기간을 제목 아래 텍스트로 표시한다. 우선 모바일 기본 지표 1개, 나머지는 명시 선택으로 제한하고 여러 단위가 필요할 때 별도 소형 차트/전환 보기로 나눈다. 수용: 포인터 없이 동일 기간의 지역별 주요 값을 표에서 비교하고 시리즈/기간을 변경할 수 있다. 근거: regions-chart-320.png, charts.js, regions.md.

3. **P1 — 작은 설명의 대비를 본문 수준으로 맞춘다.** 홈 insight-meta/detail 12.48px, article-meta 12px에 faint 토큰을 쓴다. light 토큰 #8a8f98는 흰 카드 대비 3.25:1, 바탕 #f7f6f3 대비 3.01:1이다. dark #7d838d도 카드 #1c1f24에서 4.33:1이다. 출처·기간·‘같은 집의 가격 변화와 다를 수 있음’은 해석에 필요한 본문이므로 faint 대신 muted를 사용하고 13–14px로 올린다. 장식용 메타만 한 단계 낮춘다. 수용: 정상 크기 필수 텍스트 4.5:1 이상, 키보드 focus 3px/offset3px의 기존 가시성 유지, light/dark 모두 확인. light는 토큰 대비 계산이며 전체 실화면 검증은 하지 않았다. 근거: home-1440.png, home-390.png, style.css 토큰/insight-meta/article-meta.

4. **P2 — 차트에서 글자를 키우기 전에 눈금·범례 수를 줄인다.** SVG 축/단위 실측 10px, 범례11px, tooltip 설정12px다. 320의 지역 차트 콘텐츠 폭은254px이며 좌우 y축·범례페이지·20px zoom에 정보가 몰린다. 축12px/범례12–13px, 중요한 tooltip14px를 목표로 x축 눈금3–4개, y축4–5개만 남기고 tooltip은 날짜→시리즈→값+단위 순서로 정렬한다. 억/만/건/%를 값과 함께 보이고 축 제목의 기준 단위를 일치시킨다. raw 데이터 정밀도와 표시 반올림은 별도 구현 범위다. 수용: 320에서 축 단위·첫/마지막 기간·선택값이 겹치지 않으며 tooltip은 화면 밖으로 나가지 않고 값이 한 줄로 읽힌다. 근거: regions-chart-320.png, budget-chart-390.png, charts.js와 budget/trades/regions의 axisLabel 설정. 실제 pointer tooltip의 모든 시리즈 조합은 확인하지 않았다.

5. **P2 — 필터는 글자 축소보다 단계와 그룹으로 압축한다.** 390에서 실거래 필터285px, 지역439.5px, 예산333px. label11.36px, 선택chip12px, 선택 높이38px, 입력/검색42px다. 지역은 KPI 없이 차트가 아래로 밀린다. 첫 줄에는 지역·기간, 두 번째에 현재 평형/지표 요약과 ‘상세 조건’을 두고 부차 옵션을 접되 선택 상태·초기화는 항상 보인다. 예산의 매수가/현금·소득/금리 2열은 유지하되 각 입력 label과 단위를 13px 이상으로 한다. 선택chip은 텍스트를 키워도 44px 내외 hit area를 유지한다. 수용: 390에서 기본 필터≤260px(제품 목표), 320에서는 자연스러운 줄바꿈을 허용하며 가로스크롤로 숨은 선택chip이 있다는 표시와 키보드 이동이 있다. 정보 누락을 피하기 위해 260px 고정 높이를 강제하지 않는다. 근거: trades-390.png, regions-390.png, budget-390.png.

6. **P2 — KPI 예약 높이를 정보량에 맞추고 하위 설명을 살린다.** KPI 390에서 폭173px/내부139px, 값21.45px, sub11.68px, 카드180px다. 예산 ‘현금 여유’ 등 짧은 카드는 아래가 비지만 ‘취득세…중개수수료 제외’ 같은 필수 설명은 작게 두 줄로 접힌다. 값24–28px, 제목13px, 설명13px로 계층을 잡고 금액+단위를 같은 의미 덩어리로 유지한다. 모바일 기본 높이는 약152–168px 범위로 사전 예약하되 해당 행의 긴 문구에 맞춰 동일 높이가 늘어나게 한다. loading 때만 크고 mount 후 줄이는 방식은 피한다. 데이터·웹폰트가 오기 전에도 같은 breakpoint·같은 문구 길이 기준으로 슬롯을 계산한다. 수용: 긴 금액/음수/없음/두 줄 설명에서도 잘림 없음, 값과 단위 중간에서 무의미한 줄바꿈 없음, 초기 로딩 및 필터 변경의 예상치 못한 이동 없음. 실제 CLS 수치는 측정하지 않았으므로 배포 전 계측이 필요하다. 근거: budget-390.png, trades-390.png, style.css kpi-slot min-height180px.

7. **P2 — 설명 버튼은 밀도 조절에서 보호한다.** chart-info summary는 데스크톱28×28, 모바일32×32px, 아이콘16px다. summary에 명시적 aria-label이 있고 focus outline3px/offset3px를 직접 확인했다. /budget 설명을 클릭하면 390에서 패널은324px 폭으로 카드 안에 잘 맞았다. 이 기능은 단위/비용 제외/신고지연 해석의 핵심이므로 숨기거나 hover 전용으로 바꾸지 않는다. 44px 투명 hit area 안에16px 아이콘을 유지하고 제목은 줄바꿈시키며 아이콘은 수축시키지 않는다. 수용: 320에서 긴 제목+설명 버튼이 겹치지 않고 Tab/Enter/Space로 열고 닫히며 포커스가 보인다. 패널13–14px/1.6–1.7, 최대 높이 제한시 스크롤을 키보드로 이용할 수 있다. 근거: budget-info-390.png, style.css chart-info. 클릭 개폐와 focus 스타일은 확인했으나 전체 키보드 시퀀스는 추가 검증 대상이다.

## 권장 type scale 및 간격 규칙

| 용도 | 1440 | 390/320 | 규칙 |
|---|---:|---:|---|
| 페이지 제목 | 32–36px | 26–28px | line-height1.25, 긴 제목 줄바꿈 |
| 섹션 제목 | 17–18px | 16px | line-height1.45, 설명 버튼 hit area와 정렬 |
| 본문·핵심 맥락 | 15–16px | 14–16px | line-height1.6, 60–68ch |
| KPI 값 | 28–32px | 24–28px | tnum, 금액 단위 묶기, 음수 부호 보존 |
| KPI 제목/설명·필터label | 13–14px | 13px | 설명1.5–1.6, 필수 정보4.5:1 |
| 표 본문 | 14px | 13–14px | 숫자 우측 정렬, 행44–52px, inset10–12px |
| 차트 축/범례 | 12–13px | 12–13px | 작은 폭은 눈금/시리즈를 줄임 |
| 차트 tooltip | 14px | 14px | 날짜·시리즈·값+단위, line-height1.5 |

공통 spacing은 4/8/12/16/24px로 정리한다. 모바일 카드 padding16px 유지, 제목→내용12px, 필터label→입력6–8px, 필드 간12–16px. 터치 컨트롤은 원칙44px, 인접 아이콘은44px 투명 영역을 쓰고 시각 크기는 강제 확대하지 않는다. 표는 전 열의 동시 노출보다 주요 열 우선 + 접근 가능한 상세 펼침을 우선한다. 차트·표 높이 예약은 유지하되 모든 상태에 같은 큰 빈 영역을 강제하지 말고 대표 행/페이지 규격으로 사전 예약한다.

## 확인 범위와 잔여 위험

기능 구현·코드 수정·배포는 하지 않았다. 실제 보조공학(VoiceOver), iOS Safari, 200% 텍스트 확대, 전체 tooltip 조합, light 화면, CLS 실측은 확인하지 않았다. 스크린샷의 dark 화면 판정과 DOM/설정 근거를 구분했으며 특히 키보드 표 상세/차트 대체 접근은 배포 전 기능 검증이 필요하다.
