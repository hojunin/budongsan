# Senior Product Designer 리뷰 — 매수·전월세 콘텐츠와 대표 그래픽

2026-11-07. 대상: [제품 설계](../superpowers/specs/2026-11-07-real-estate-content-platform-design.md) 1–13절과 [기존 디자인 리뷰](2026-11-07-product-design-review.md). 이번에는 설계의 정보 구조·인터랙션·독자 여정·시각화 의미·시스템 일관성·모바일/접근성·출시 범위를 검토했다. 신규 화면의 시안/프로토타입이 없으므로 픽셀 완성도나 실제 가독성을 통과 판정하지 않는다. 아래는 리뷰 제안이며 구현 완료나 사용자 승인을 뜻하지 않는다.

## 판정

**방향 유지, 대표 화면의 의미와 기본 상태를 보완한 뒤 시안 제작.** ‘같은 돈, 다른 선택’은 첫 대표 기능으로 적합하지만, 세 그래픽 모두 동등한 비중으로 출시하면 다시 분석 대시보드가 복잡해질 위험이 있다. 가격/비용의 원값, 비교 조건, 그 뒤에 가능한 행동을 먼저 설계해야 한다.

강점: 매수와 임차를 별도 질문으로 다룬 점, 글과 차트를 같은 데이터 시점에 고정하는 점, 기존 라이브러리 재사용, 출처/표본/날짜를 숨기지 않는 점. 가장 큰 미완성 부분은 색상표가 아니라 ‘독자가 화면에서 무엇을 판단하고 다음에 무엇을 하는가’다.

## 우선순위별 발견

### P1-1. ‘내 예산’의 의미가 두 개라 첫 그래픽의 약속이 모호하다

근거: 설계 13절은 거래가격 분포에 ‘내 예산 세로선’을 표시한다. 1·3절은 실제 자금 시나리오도 연결한다. 집값 상한, 보유 현금, 대출을 포함한 총 구매가능액은 다른 값이다.

영향: 현금 3억을 입력한 사람이 거래가 3억 구간을 보거나, 집값 8억을 설정하고 실제 매수 가능 판정을 받았다고 생각할 수 있다. 이는 문구가 아니라 제품 의미의 문제다.

제안: 첫 화면 입력은 **‘비교할 집값 상한’**으로 한정한다. 보조 문구는 ‘최근 거래가격 비교 · 대출/부대비용 제외’ 한 줄. ‘내 자금으로 계산’은 별도 명시 행동으로 기존 계산기에 연결한다. 자동으로 LTV를 곱해 상한을 만들지 않는다. 예산선의 이름도 ‘집값 상한’으로 통일한다.

수용: 별도 설명 없이 사용자가 입력값이 집값인지 보유현금인지 구분하고, 이 결과가 대출 승인/구매가능 매물 목록이 아니라는 점을 이해한다.

### P1-2. 가운데 50% 가격 띠는 매물 범위·최저/최고가처럼 보일 수 있다

근거: 13절은 중간 50% 구간+중간값을 사용하지만 명시 라벨·선택/결측 상태의 모양은 정해지지 않았다.

제안: 제목을 **‘최근 거래가격 비교’**, 표식에 ‘중간 거래가’, 띠에 ‘거래의 가운데 50%’를 직접 표기한다. 현재 매물색/매물 수 배지와 혼용하지 않는다. 상세에서 전체 거래점과 범위 밖 거래를 확인할 수 있게 한다. ‘적정가’, ‘저평가’, ‘이 가격에 구매 가능’이라는 이름은 쓰지 않는다.

수용: 사용자가 띠를 최저~최고가 또는 현재 매물 호가로 설명하지 않는다. 예산 밖도 가로축에서 잘라 숨기지 않고, 예산선이 화면 밖이면 ‘상한 X억: 표시 범위 밖’과 축 확장 버튼을 제공한다.

### P1-3. 같은 면적대라는 이유만으로 동등 비교처럼 보인다

근거: 3·8·13절은 동일 면적대/기간을 사용한다. 현재 band는 여러 실제 면적을 포함하므로 단지별 면적 구성·연식·층·최근 거래 시점이 다를 수 있다.

제안: 각 행에 **단지명 / 전용면적 범위 / 연식 / 거래 n건 / 마지막 거래월**을 표시하고 조건 불일치는 비교표 상단에 짧게 밝힌다. 동일 면적을 못 맞추면 다른 면적임을 드러낸 상태로 비교하거나 조건 수정으로 유도한다. 누락값을 임의로 보정해 단일 순위를 만들지 않는다. 표본수는 신뢰 점수로 바꾸지 않는다.

수용: 사용자에게 ‘왜 A와 B 가격이 다른가’를 물었을 때 크기·연식·표본 차이를 화면에서 찾을 수 있다. 동일기간 양쪽 표본이 없는 증감률은 비운다.

### P1-4. 월세 산점도가 첫 질문의 답보다 먼저 나온다

근거: 13절은 보증금×월세 산점도에서 거래3개를 고른 후 환산비용 막대를 제공한다. 일반 독자는 두 축을 해석하고 점을 골라야 월 부담을 알 수 있다.

제안: 기본 뷰는 **‘보증금 / 실제 월세 / 가정 반영 월 비용’ 비교 행 2–3개**다. 아직 고르지 않았다면 중립적인 예시가 아닌 실제 조건 검색 결과와 ‘비교 추가’ 버튼을 제공한다. 산점도는 ‘전체 거래 분포’로 펼친다. ‘낮은 부담순’ 정렬을 제공할 때는 선택 금리 기준임을 표시하고 초기 추천순은 두지 않는다.

수용: 독자가 산점도를 조작하지 않아도 두 계약의 원래 보증금·월세와 선택 가정의 차이를 읽을 수 있다. 총 환산비용보다 실제 납부 월세를 숨기지 않는다.

### P1-5. 동기화된 날짜 커서가 서로 다른 기준일을 같은 시점으로 보이게 한다

근거: 13절의 변화 카드는 날짜 기준선을 함께 움직인다. 데이터는 주간/월간, 발표 지연도 다르다. 설계가 미발표값 채우기를 금지한 것은 좋지만 선택 시각의 대체값 표시가 미정이다.

제안: 월 단위 비교는 공통 완료월을 기본값으로 삼는다. 주간지표를 별도 유지하면 각 패널에 실제 관측 기간을 표시한다. 선택일 값이 없으면 ‘해당 기간 자료 없음’. 직전 값 참조는 사용자가 ‘가장 가까운 이전 발표’ 모드를 선택한 경우만 하고 그 날짜를 표시한다. 선의 보간점이 실제 관측값처럼 tooltip에 나타나지 않게 한다.

수용: 커서 이동으로 전월 수치가 이번 달 수치처럼 표시되지 않는다. 월 거래량을 주간 가격과 같은 비율로 자동 분할하지 않는다.

### P1-6. 아름다운 비교 다음에 독자가 할 행동이 약하다

근거: 4절은 독자에게 출처·관련 글·조건 링크, 5절은 작성자의 저장/초안 흐름이 구체적이다. 공개 독자의 후보 유지·비교 복귀는 없다.

제안: 공개 독자의 주요 행동은 **‘비교에 담기 → 조건 바꿔 보기 → 관련 거래/비용 확인’**이다. 작성자의 ‘근거 저장/스토리 만들기’와 섞지 않는다. 첫 단계는 계정 없이 현재 브라우저의 후보2–3개 유지와 비교 조건 복원으로 충분하다. 보유현금/소득 같은 개인 입력은 공유 URL에 기본 포함하지 않는다. 공유 범위는 미리보기에서 명시한다.

수용: 글→단지→비교→글 복귀 시 지역·면적·기간이 보존되고, 초보 독자에게 내부 발행 버튼이 보이지 않는다. 이 기능은 기존 설계에 추가할 범위이므로 별도 구현 작업으로 다룬다.

### P2-1. 문구를 줄여도 핵심 판단까지 info 안으로 밀어 넣으면 안 된다

근거: 4·13절은 정의를 info로 이동하고 출처/기준일/표본은 유지한다. 실제 화면에서 필수 정보와 설명의 위치가 아직 없다.

제안: 그래픽의 읽는 순서를 **질문 → 비교 그림 → 한 줄 관측 → 기준일·표본 → 상세 정의**로 고정한다. 긴 안내·파일명·복사 방법은 제거한다. ‘임대 비용 가정 4%’는 결과 가까이 둔다. info는 중간값/분위수 계산법만 맡는다. 표본 부족이나 잠정 수치는 해당 값 옆에 중립 배지+읽을 수 있는 이름을 둔다.

수용: info를 한 번도 열지 않은 독자도 무엇을 언제 얼마나 비교했는지 알 수 있다. source 링크는 보이되 3장의 모든 그래픽에 긴 기관명을 여러 번 크게 반복하지 않는다.

### P2-2. 공유 이미지의 기준일·표본·가정이 1장씩 떨어질 수 있다

근거: 13절은 3장 콘텐츠와 모든 출력의 출처·기준일을 명시했지만 문맥의 완결성은 미정이다.

제안: **각 장이 단독 공유돼도 성립**하게 제목, 지역/면적/기간, 단위, 필요한 가정, 출처를 포함한다. 카드의 여백을 줄여 모두 밀어 넣기보다 차트/문장을 줄인다. 출처는 짧은 기관명+읽을 수 있는 날짜, 상세는 QR/짧은 원문 링크로 연결한다. QR만 유일한 접근 경로로 삼지 않는다.

수용: 카드1만 받은 사람도 어떤 지역/기간/주택형 수치인지 알 수 있다. 1080px 이미지도 360px 화면에 축소해 글자·각주를 확인한다. 출력 프리셋 수가 아니라 작은 화면에서의 읽기가 완료 기준이다.

### P2-3. 선택 강조와 지역 고정색의 역할이 충돌할 수 있다

근거: 기존 디자인 리뷰는 지역색 고정, 13절은 선택 대상 강조를 요구한다. 구현자가 선택한 지역을 모두 Teal로 바꾸면 지역 동일성이 사라진다.

제안: **Teal=조작/선택 컨트롤, 지역색=데이터 ID**. 선택한 행은 테두리·굵기·텍스트 표시로 강조하고 시리즈색은 유지한다. 임대 계약 A/B/C는 지역색 대신 별도 비교 대상 ID 매핑을 사용한다. ‘중립+선택 한 색’ 비교그래픽과 ‘고정 다지역색’ 추이그래픽의 허용 용례를 구분한다.

수용: 페이지/선택/내보내기를 바꿔도 서울이나 계약A가 다른 색으로 바뀌지 않는다. 흑백 출력에서도 직접 라벨·선형·마커로 구분된다.

### P2-4. 발행 대기 상태에서 사용자가 할 수 있는 행동이 부족하다

근거: 6절에 Mac 오프라인·queued/delayed/failed가 정의돼 있다. 기술 상태를 사용자에게 얼마나 노출할지는 미정이다.

제안: 화면은 ‘초안 / 검토 준비 / 발행 대기 / 공개됨 / 확인 필요’의 언어로 묶는다. 상태 세부 이유는 펼친다. 대기에는 요청 시각·마지막 연결·‘요청 취소’, 실패에는 보존된 초안·‘다시 확인’, 완료에는 공개 링크를 제공한다. 배포를 시작해 취소할 수 없는 상태는 버튼을 없애는 대신 ‘발행 중에는 수정할 수 없습니다’를 해당 위치에 표시한다. 성공 toast만으로 공개 완료를 알리지 않는다.

수용: 사용자가 Mac 연결 상태나 배포 ID를 이해하지 않아도 글이 공개됐는지, 지금 무엇을 할 수 있는지 구분한다. 로컬 단계A에 아직 없는 웹 버튼을 노출하지 않는다.

## 대표 화면의 권장 구성

### 매수 비교 — 첫 시안에서 확인할 구조

1. 제목: ‘최근 거래가격 비교’. 보조 질문: ‘정한 집값 상한과 후보 단지의 거래는 얼마나 차이 날까요?’
2. 짧은 조건 줄: 매매/전세, 지역, 면적, 최근 완료6개월. 고급 조건은 펼침.
3. 입력: ‘비교할 집값 상한’ + 금액. 후보 추가는 최대3개.
4. 본문: 공통 가로축, 단지별 구간/중간값, 상한 세로선. 행마다 면적·연식·n건·마지막 거래월.
5. 행동: 후보별 ‘거래 보기’, 공통 ‘내 자금으로 계산’. 작성 기능은 공개 화면에서 숨김.
6. 하단: 출처·관측 기간·취소 제외 여부, 정의 info. 현재 매물 목록처럼 꾸미지 않음.

모바일은 동일 축의 단지 행을 세로로 쌓는다. 행마다 독립 축을 자동 확대하지 않는다. 320px에서 단지명이 길면 라벨 줄바꿈을 허용하고 메타는 아래 줄로 보낸다. 터치로 거래를 선택한 뒤 외부 스크롤을 막지 않는다. 차트 조작 없이 같은 값을 읽는 비교표를 제공한다.

### 전월세 — 기본과 상세 분리

기본은 선택 계약의 보증금·월세·환산비용 비교. 금리 가정은 결과 옆에 짧게 표시하고 수정 버튼으로 연다. 상세 분포는 그 아래 접는다. 금리 변경 후 어떤 계산값만 바뀌었는지 강조하되 행 순서·페이지 높이가 갑자기 바뀌지 않게 한다. 자동 정렬로 사용자가 보고 있던 계약이 이동하지 않도록 정렬 실행은 명시 조작으로 둔다.

## 출시 범위와 판단 기준

- 먼저 만들 것: 대표 매수 비교1개, 모바일 비교표, 근거/출력물의 일관성. 매매/전세 가격 비교를 같은 문법으로 재사용.
- 다음: 임대 비용 비교, 그 뒤 동기화된 변화 카드. 새로운 CMS/AI/신규 API 전체를 첫 시안에 넣지 않는다.
