## 검사 방식과 판정

현재 수집 계약과 신규 명세를 별도 조사한 뒤, 이를 카탈로그와 함께 서로 다른 검토자2명에게 제공했다. 방법론 검토자는 식/분모/단위/기간/표본/기존 필드의 의미를, 제품·편집 검토자는 독자 결정 가치/그래픽 오해/모바일/공개 문구를 각 ID별로 검사했다. 지적 수정 뒤 같은 검토자가 변경 사항을 다시 확인했고 최초 의견도 보존했다.

최종 결과: **설계 문서의 지적 사항은 해소했고, 재검토에서 남은 중대한 방법론·제품/편집 문제는 발견되지 않았다.** 두 검토자 모두 의미 있는 관측 설계가10개 이상 남는다고 판단했다. 이는 모든 인사이트가 즉시 제공 가능하거나 통계적으로 유의하다는 뜻이 아니다.

20개 구성은 **시장 관측17개 + 비용 시나리오2개(I08/I15) + 데이터 품질1개(I14)**다. 단순히 전부 ‘시장 인사이트20개’라고 발행하지 않는다. 기존 원천 경로를 이용하는 정의14개(E)와 신규 소스 뒤의6개(N)를 구분하며, E도 원값/정규화/완결성/권리/스냅샷 게이트와 신규 집계 구현이 필요하다. 신규 소스 I15–I20은 운영 보류를 유지한다. 초기 표본 임계값은 제품 정책이며 대표성/정확도 보장이 아니다.

## 검사에서 수정한 주요 내용

| 지적 | 반영 |
|---|---|
| 공급면적·분양최고금액을 전용면적·대표 분양가처럼 쓰는 위험 | API가 실제 제공하는 의미로 명명. 면적 증거 없으면 ㎡당/면적일치/차익 비교 차단 |
| 보증금 구간 고정이 보증금 자체 고정처럼 표현됨 | 구간 내 보증금 중간값/분포도 표시, 같은 보증금 월세인상 주장 차단 |
| 인구·세대 원천 계약 빠짐 | 공식 월간 화면과 알려진 라벨을 등록하되 파일/필터/사용권 미확정을 명시 |
| 최근3개월을 달력 분기로 표기 | 실제 시작–종료월과 지수 기준월을 각각 표시 |
| 한기간 전세·매매 수준 비교를 변화 질문으로 표현 | 한기간 집단 차이 질문으로 축소 |
| 환산비용을 실제 월 현금 부담처럼 명명 | 실제 보증금/납부월세를 먼저, 가정 환산비용을 별도로 표시 |
| 공통/개별 최소 표본 충돌 | ID별 최종 정책표로 단일화, I07 비교셀 양기간 n≥30 |
| 미분양 전체+준공후 중복 누적 위험 | (전체−준공후)+준공후의 한시점 구성막대로 명시 |
| 준비도/선택색/모바일 그래픽 해석 | 내부 E/N과 독자 상태 분리, 공통축/대체표/범위밖 예산선 규칙 명시 |
| 원본 이력·단위·분류의 추가 한계 | 합성표본 거부, 미상 직거래3상태, 원값 price/area 계산, 과거 전체lookback·이전분자0·회전율100%초과 등 명시 |

현재 구현 감사에서 추가로 파악한 오류응답/정상0건 구분, 페이지 완결성, KB 부분성공 범위 보존 문제는 **수집기 구현의 후속 과제**다. 이 문서 작업에서 수정하거나 실제 손상을 판정하지 않았다.

## 가장 작은 다음 구현

1. 실패/0건·페이지완결·커버리지 기록, 임대 월세미상/직거래미상 정규화, 안정 단지 매핑부터 보완.
2. I09/I05 매수 비교, I06/I08 전월세 비교, I01/I03 브리핑을 첫 수직 기능으로 구현.
3. 각 산식/차단조건의 합성 fixture 테스트 후 승인된 원천 fixture와 읽기전용 실제 스냅샷으로 대조.
4. 320/390/1440 화면·키보드/VoiceOver·문장 오해 과제·CLS·출력물 일치 검증 뒤 공개.
5. 신규 API 계약을 확정한 항목만 N→검증 가능 상태로 전환. 기존 입력에 없던 데이터는 샘플로 대체 발행하지 않음.

파일 검사: I01–I20 고유 정의20개와 로컬 문서 링크를 확인했고 diff 공백 검사 통과. 앱 코드가 바뀌지 않아 앱 빌드/실행 테스트는 하지 않았다. 공식 명세 존재가 인증 응답·커버리지·권리 승인을 대신하지 않는 점이 남은 핵심 제약이다.
